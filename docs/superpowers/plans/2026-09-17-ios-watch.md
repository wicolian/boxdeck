# iOS and watchOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a tested shared Apple client, an iOS dashboard and action app, an independent watchOS needs-you app, pairing support in the Go deck, and CI that builds the Apple targets.

**Architecture:** `apple/BoxdeckKit` owns Codable API models, URLSession transport, Keychain-backed box configuration, SSE events, menu summaries, and quiet-hour logic. The iOS and watchOS targets are thin SwiftUI clients over that package. The Go server owns fresh pairing token creation and QR generation, while the deck Settings page exposes the QR response.

**Tech Stack:** Swift 5.10, Swift Package Manager, SwiftUI, URLSession, Security, WatchConnectivity, WebKit, AVFoundation, XcodeGen, GitHub Actions, Go standard library.

**Spec:** `.work/phase5/PROMPT-ios.md`

## Global Constraints

- Support iOS 17, watchOS 10, and macOS 13 package clients.
- Every network request uses bearer auth and a five second timeout unless it is an SSE stream.
- No credentials are written to reports or screenshots.
- Pairing creates a fresh token labeled `phone` and never returns an existing token.
- iOS and watchOS remain usable with no configured box and show honest empty or unreachable states.
- No gradients, no icon soup, and no middle dot, em dash, or en dash in changed text.
- CI uses `CODE_SIGNING_ALLOWED=NO` for simulator builds and uploads zipped app folders.
